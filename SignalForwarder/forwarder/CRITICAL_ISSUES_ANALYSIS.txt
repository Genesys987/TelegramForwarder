CRITICAL ISSUES IDENTIFIED IN THE LOGIC AND TEST SCENARIOS
=========================================================

## Fixed Issues:
1. ✅ **getMT4DataFolderId trailing slash bug**: Fixed to handle both Unix and Windows path separators

## Identified Potential Issues:

### 1. **Array Bounds Issue in MT4 EA**
**Problem**: The EA declares `tpLevels[20]` but doesn't check if `tpCount` exceeds 20
**Location**: `TelegramSignalForwarder.mq4` lines 120, 252
**Risk**: Array bounds overflow if signal has >20 TP levels
**Fix needed**: Add bounds checking before ArrayResize

### 2. **Signal Parsing Limitations**
**Problem**: Parser fails on certain signal formats (test showed many failures)
**Location**: `signal_parser.py` parse_signal function
**Risk**: Valid signals rejected, trading opportunities missed
**Fix needed**: Improve regex patterns and format recognition

### 3. **Channel Name Truncation Loss**
**Problem**: All channel names get truncated to 4 letters, losing distinction
**Location**: `signal_parser.py` clean_channel_name function
**Example**: "CHAN0", "CHAN1", "CHAN2" all become "CHAN"
**Risk**: Cannot distinguish between different channels
**Fix needed**: Better channel name encoding/hashing

### 4. **TP Level Validation Missing**
**Problem**: No validation that TP levels are in correct order
**Location**: Both Python parser and MT4 EA
**Risk**: Invalid TP sequences (e.g., BUY with descending TPs)
**Fix needed**: Add TP order validation

### 5. **SL Validation Missing**
**Problem**: No validation that SL is on correct side of entry price
**Location**: Both Python parser and MT4 EA
**Risk**: Invalid SL placement (e.g., BUY with SL > entry)
**Fix needed**: Add SL position validation

### 6. **Duplicate TP Handling**
**Problem**: No handling of duplicate TP levels
**Location**: Signal parsing and MT4 order creation
**Risk**: Multiple orders with same TP, broker rejection
**Fix needed**: Remove duplicates or adjust slightly

### 7. **Memory Management in MT4**
**Problem**: Static array resizing and potential memory issues
**Location**: ReadSignalFile function, tpLevels array
**Risk**: Memory corruption with frequent large TP arrays
**Fix needed**: Better memory management, array pooling

### 8. **Race Conditions in File Operations**
**Problem**: Multiple processes reading/writing same files
**Location**: Queue files, signal files
**Risk**: Data corruption, lost signals
**Fix needed**: File locking, atomic operations

### 9. **Error Recovery Issues**
**Problem**: Failed orders don't have retry logic
**Location**: SendOrders function
**Risk**: Partial signal execution, inconsistent state
**Fix needed**: Retry logic, error recovery

### 10. **Lot Size Risk Management**
**Problem**: Fixed lot size for all TP levels
**Location**: SendOrders function
**Risk**: Over-leveraging with many TP levels
**Fix needed**: Dynamic lot sizing based on TP count

## Test Scenarios That Would Fail:

### Scenario 1: Large TP Count Signal
```
Signal with 25 TP levels → Array bounds overflow in MT4
```

### Scenario 2: Invalid TP Order
```
BUY EURUSD
ENTRY 1.1234
TP1 1.1300 (correct)
TP2 1.1250 (wrong - should be higher)
TP3 1.1200 (wrong - should be highest)
SL 1.1200
```

### Scenario 3: Invalid SL Position
```
BUY EURUSD
ENTRY 1.1234
TP 1.1250
SL 1.1240 (wrong - SL above entry for BUY)
```

### Scenario 4: Duplicate TPs
```
BUY EURUSD
ENTRY 1.1234
TP1 1.1250
TP2 1.1250 (duplicate)
TP3 1.1250 (duplicate)
SL 1.1200
```

### Scenario 5: Channel Name Collision
```
Channel "CHANNEL_A" → "CHAN"
Channel "CHANNEL_B" → "CHAN"
Channel "CHANNEL_C" → "CHAN"
All look identical in MT4 comments
```

### Scenario 6: Rapid Signal Burst
```
10 signals within 1 second → File lock conflicts, data corruption
```

### Scenario 7: Very Long Signal Message
```
Signal with 50 TP levels → Message too long for MT4, parsing fails
```

### Scenario 8: Malformed Signal Recovery
```
Corrupted signal in queue → Entire queue processing stops
```
