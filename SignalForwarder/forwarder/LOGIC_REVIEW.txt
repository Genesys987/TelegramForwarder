// ========================================
// IDENTIFIED POTENTIAL ISSUES:
// ========================================

/**
 * ISSUE 1: Array bounds in ReadSignalFile
 * - tpLevels[20] is hardcoded but no bounds checking
 * - What if signal has 25 TPs?
 */

/**
 * ISSUE 2: Color array cycling
 * - Only 6 colors defined: {clrBlue, clrGreen, clrRed, clrYellow, clrMagenta, clrCyan}
 * - With 10+ TPs, colors will repeat
 * - Not critical but confusing visually
 */

/**
 * ISSUE 3: No validation on TP count
 * - Should there be a maximum TP limit?
 * - What about minimum distance between TPs?
 */

/**
 * ISSUE 4: Lot size distribution
 * - All orders use same lot size
 * - With many TPs, total position size grows linearly
 * - Risk management issue
 */

/**
 * ISSUE 5: Performance with many orders
 * - OrderSend() called in loop without delay
 * - Might hit broker rate limits
 * - Should add small delay between orders?
 */

/**
 * ISSUE 6: Backward compatibility edge cases
 * - What if old 3-TP signal has empty TPs?
 * - tp2 = tpCount > 1 ? tpLevels[1] : tpLevels[0];
 * - This creates duplicate TP values for old code compatibility
 */

/**
 * ISSUE 7: TP ordering validation
 * - No validation that TPs are in correct order
 * - BUY: TPs should be > entry price
 * - SELL: TPs should be < entry price
 * - No validation that TPs are sequential
 */

/**
 * ISSUE 8: Entry price vs current price logic
 * - Removed missedTP1 logic entirely
 * - What about limit vs market order decision?
 * - midPrice calculation still uses tp1, but might not be tpLevels[0]
 */

/**
 * ISSUE 9: Memory management
 * - tpLevels[20] allocated on stack in start()
 * - ArrayResize() called in ReadSignalFile()
 * - Potential memory issues with frequent calls
 */

/**
 * ISSUE 10: Error handling
 * - If one OrderSend() fails, others still execute
 * - Should there be rollback mechanism?
 * - Partial fill scenarios not handled
 */
